# การใช้งานครั้งแรก

หลังระบบรันและล็อกอินเป็นผู้ดูแลได้แล้ว (ไม่ว่าจะติดตั้งแบบ Native หรือ Docker)
ตอนนี้มีแค่ผู้ดูแล 1 คน ต้องเพิ่มผู้ใช้อื่นและตั้งผู้อนุมัติก่อนระบบจะทำงานครบวงจร

## นำเข้าผู้ใช้ + มอบบทบาทผู้อนุมัติ

1. ล็อกอินเป็นผู้ดูแล → เมนู **การจัดการ → จัดการผู้ใช้งาน**
2. **ดาวน์โหลดเทมเพลต Excel** → กรอกข้อมูลผู้ใช้
   - คอลัมน์ **เลขที่ตำแหน่ง** จำเป็นทุกคน
   - คอลัมน์ยอดคงเหลือ (ลาป่วย/ลากิจ/ลาพักผ่อนคงเหลือ) จะใส่หรือไม่ก็ได้ — ถ้าไม่ใส่ ระบบตั้งยอดเริ่มต้นตามสิทธิ์ให้
3. **นำเข้าไฟล์ Excel** → ระบบแจ้งจำนวนสำเร็จ/ล้มเหลว พร้อมเหตุผลรายแถว (เช่น สาขาสะกดผิด → แนะนำชื่อที่ใกล้เคียง)
4. **มอบบทบาทผู้อนุมัติ** (แท็บ *จัดการผู้อนุมัติ*): กำหนด `VERIFIER`, `APPROVER_1` (หัวหน้าสาขา), `APPROVER_2/3/4`

::: warning จำเป็นเสมอ — ต้องมี VERIFIER
ต้องมี **VERIFIER** อย่างน้อย 1 คน ไม่งั้น**การยื่นลาจะล้มเหลว** (ระบบต้องมีผู้ตรวจสอบเพื่อออกเลขที่ใบลา)
:::

::: tip Checkpoint
ผู้ใช้ทั่วไปล็อกอินแล้วยื่นลาได้ และคำขอไหลไปถึงผู้อนุมัติ
:::

## สายอนุมัติ (ลำดับการพิจารณา)

เอกสารการลาจะไหลตามลำดับนี้ หากขั้นใดปฏิเสธ คำขอจะหยุดและแจ้งเหตุผลกลับ

| ลำดับ | บทบาท | หน้าที่ |
|-------|-------|---------|
| 1 | หัวหน้าสาขา (`APPROVER_1`) | อนุมัติขั้นแรก (เฉพาะคนในสาขาตนเอง) |
| 2 | ผู้ตรวจสอบ (`VERIFIER`) | ตรวจสอบ + ออกเลขที่ใบลา |
| 3 | สารบรรณคณะ (`APPROVER_2`) | — |
| 4 | รองคณบดี (`APPROVER_3`) | — |
| 5 | คณบดี (`APPROVER_4`) | อนุมัติขั้นสุดท้าย |

## บทบาทในระบบ

| บทบาท | คำอธิบาย |
|-------|---------|
| `USER` | ผู้ใช้ทั่วไป — ยื่นลาและดูยอดวันลา/ประวัติของตนเอง |
| `APPROVER_1` | หัวหน้าสาขา — อนุมัติขั้นแรก (เฉพาะคนในสาขาตนเอง) |
| `VERIFIER` | ผู้ตรวจสอบระดับคณะ — ให้ผ่าน/ไม่ผ่าน และออกเลขที่ใบลา |
| `APPROVER_2/3/4` | สารบรรณคณะ / รองคณบดี / คณบดี (ระดับคณะ) |
| `ADMIN` | ผู้ดูแล — จัดการข้อมูลหลักและผู้ใช้ |
| `SUPER_ADMIN` | ผู้ดูแลขั้นสูง — มีสิทธิ์ ADMIN ทั้งหมด + ข้อมูลที่อ่อนไหว |

::: info เกร็ด: เงื่อนไขวันลา (Rank)
สิทธิ์วันลาของแต่ละ **ประเภทบุคลากร × ประเภทการลา** กำหนดจากข้อมูล **Rank** (seed ใส่ให้ 75 รายการแล้ว)
ปรับได้ที่เมนูผู้ดูแลระดับสูง → เงื่อนไขวันลา (Rank)
:::
